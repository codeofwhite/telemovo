# 故障排查

## 页面无法访问

先确认网关打印了 `gateway_ready`，绑定的是当前服务器 LAN IP，而非默认环回地址。
使用正确的 `https://IP:端口/health`。Franka 默认 8444、X5 默认 8445。
IP 换网后需要更新绑定参数和证书 SAN；页面没有固定原实验 IP。
检查 PICO 是否在访客网络、是否启用 AP 隔离，以及本机防火墙端口。
`/health` 成功仅证明网关可用，不证明仿真或 SSH 隧道可用。

## 页面能打开，但无场景

查看网关是否出现 `upstream_unavailable`，确认仿真初始化完成并监听环回端口。
远端方式需要 SSH 主机认证已配置、隧道持续运行。X5 首次几何包较大，不能用一张
静态截图推断状态流已经正常。状态断开后需刷新重连，不会在后台无限自动重试。

如果提示模型或补丁缺失，按错误信息修复明确依赖。不要换到未知 Genesis 版本或绕过
校验。新版 Genesis 接口变化需要重新验证，不能只更新版本号。

## VR 入口不可用

确认 PICO 浏览器支持 WebXR、证书受信任、使用 HTTPS，且已经收到了场景。
桌面浏览器能显示预览不表示它支持 `immersive-vr`。自签证书的继续访问行为依浏览器
而异；必要时先建立证书信任，再检查 WebXR 能力。

## 手柄无响应

检查服务端是否带 `--teleop`，网页是否为 `/?teleop=1`。戴好头显，让双手柄在跟踪范围内。
先松开两侧 Grip，再按住一侧小幅移动。无效追踪、输入过期、跳变、工作空间或跟踪误差
都可能要求松 Grip 后再操作。看状态提示，不要通过提高限位门槛来消除报错。

默认旋转锁定意味着转手腕不会改变夹爪朝向。若要测试旋转，先松 Grip，选“跟随手腕旋转”。
Trigger 开合也需要有效追踪并完成松 Grip 解锁；它不是录制开关。

## 画面流畅但机器人更新慢

本地头部绘制与远端物理是两条节奏。头部跟随流畅、输入发送 60Hz，不代表物理实时。
同时查看 RTF、状态发布率、输入年龄和实际头显 FPS；确认 GPU 共享负载。
先停录像、区分有无接触／相机渲染的耗时，再设计对照，避免直接改布料材料掩盖瓶颈。

## 衣物滑动、弹跳、抓不起或看似粘住

检查是否应用指定接触补丁、指腹模型是否匹配、是否真正把衣物夹在两侧碰撞体之间。
过大摩擦可能妨碍释放，柔软程度也不能单独解决接触几何问题。当前平台允许衣物悬边；
悬边节点可低于平台顶面，验证仍检查原桌面支撑高度。
目前 X5 抬升失败是已知结果，不应该通过节点绑定或自动黏附隐藏。

## 与早期 CloudXR 黑屏的关系

本仓库 Genesis 路径不使用 CloudXR。此前 Docker／Isaac 5.1 的原生崩溃，不能推出
“Docker 中所有遥操都行不通”，也不能当作当前 WebXR 网关的已定位故障原因。
对当前问题应先检查网关、状态连接、浏览器错误和物理状态。
